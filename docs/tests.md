# Test Suite Overview

This document summarizes the automated test coverage and how to run/extend it.

## Suites
- **Lint** (`npm run test:lint`): ESLint over the repository.
- **Unit** (`npm run test:unit`): Vitest on utilities and logic (jsdom environment). Adds coverage reporting with thresholds.
- **Component** (`npm run test:component`): Vitest + Testing Library for React components (jsdom).
- **E2E** (`npm run test:e2e`): Playwright against the built preview server.

## Current coverage focus
- Progression math: encounter cycles, expected difficulty, XP reward/level scaling.
- Achievement logic: tier detection, new unlocks under mocked achievement data.
- UI safety: Reset modal confirmation path.
- Display helpers: aura naming behavior.

## How to run locally
1. Install deps: `npm install` (or `npm ci`).
2. Run suites:
   - Lint: `npm run test:lint`
   - Unit: `npm run test:unit`
   - Component: `npm run test:component`
   - E2E: `npm run build && npm run preview -- --host 0.0.0.0 --port 4173 & npx wait-on http://127.0.0.1:4173 && npm run test:e2e`
3. Coverage report: generated by Vitest (`coverage/`), with thresholds enforced.

## Adding tests
- Prefer deterministic helpers (mock `Math.random`, `localStorage`, timers) to reduce flakes.
- For component tests, render minimal props and mock heavy dependencies (audio, large constants) when possible.
- For E2E, keep selectors stable (data-testid where practical) and upload Playwright traces on failure.

## CI
- GitHub Actions matrix runs lint/unit/component in `node:20-bookworm` and e2e in the Playwright image.
- Playwright traces uploaded on failure; Vitest coverage available locally and can be uploaded as an artifact if desired.
